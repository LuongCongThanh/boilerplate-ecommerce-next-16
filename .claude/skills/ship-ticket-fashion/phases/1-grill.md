# Phase 1 — grill + ⛔G1

Mục tiêu: hiểu ticket tới mức mỗi acceptance criterion có seam và tên test, mỗi lựa chọn mở có quyết định.

1. **Nhánh.** `git fetch origin`, rồi từ `origin/dev` tạo `<type>/<mô-tả-ngắn>` (`docs/architecture/11-git-workflow.md` mục 2; ví dụ `feat/shared-api-layer`). Đang có thay đổi chưa commit của việc khác → *Cần người dùng*. Nhánh hiện tại còn PR mở (`gh pr list --head <nhánh hiện tại> --state open`, tài khoản ở `phases/6-ship.md`) → hỏi: merge PR đó trước (khuyên dùng khi ticket mới cần code của nó), hay tách nhánh mới từ `origin/dev` luôn. Cờ `NO HOOKS` (`state.py start`) → hỏi người dùng rồi chạy `uv run pre-commit install` trong `backend/`, để gitleaks, ruff và mypy chạy ở mỗi commit thay vì đợi CI. Rồi trong `backend/` chạy `uv run python manage.py check --database default`: lỗi kết nối → *Cần người dùng*, nhờ sửa `DATABASE_URL` trong `backend/.env` theo dạng của `.env.example` (agent không đọc `.env`).
2. **State.** `python S/scripts/state.py init <T> --branch <nhánh> --mode full` (mode tạm, G1 chốt). Đọc `reference/state.md`.
3. **Nguồn.** Đọc ticket, `spec.md` của feature, mọi tài liệu và ADR ticket trỏ tới, `GLOSSARY.md`. Ticket chạm quy tắc nghiệp vụ → thêm `docs/business/04-business-rules.md`, `05-order-lifecycle.md`. Vị trí test, marker, fixture: `docs/architecture/12-testing-strategy.md`. Sau bản đồ code (bước 4), tra `docs/architecture/README.md` để tìm *tài liệu chi phối* (`reference/rules.md`) của từng file sẽ đổi, đọc đúng các mục đó.
4. **Bản đồ code** (sub-agent `Explore`, full): code hiện có mà ticket sửa hoặc gọi, và ticket nào bị ticket này chặn (`Blocked by` trỏ về nó) để chốt API cho đúng chỗ dùng sau này. Ticket bọc việc một thư viện bên thứ ba đã làm (đồng bộ lịch, migrate, xác thực…) → tìm thêm hàm của chính thư viện cho việc đó, để grilling chốt dùng lại hay tự viết và vì sao. Kết quả: danh sách file sẽ đổi, chữ ký sẽ thêm, hàm thư viện dùng lại được.
5. **Grilling.** `mattpocock-skills:grilling` trong phạm vi ticket: chốt lựa chọn còn mở và các _seam_ sẽ test (`mattpocock-skills:codebase-design` khi có module hoặc interface mới). Code chuyển ra khỏi một `except` rộng (`except Exception` của handler, của transaction): liệt kê mọi exception nó từng được bắt ở đó và chốt nơi mỗi loại rơi vào sau khi chuyển. Lite: chỉ hỏi phần mà ticket và tài liệu chưa trả lời.
6. **Ghi quyết định** vào `spec.md` của ticket, mục `## Quyết định` đặt trước `## Acceptance criteria`: dòng đầu `Chốt khi grilling ngày DD/MM/YYYY.`, rồi bảng Chủ đề | Quyết định, như `.scratch/backend-bootstrap/issues/09-shared-core/spec.md`. Dòng đầu bảng là `Tài liệu chi phối`: mỗi file hoặc nhóm file sẽ đổi → mục tài liệu (`02 §9.1`, `04 §3`, `ADR 0007`); model và test luôn kèm `02 §9.2` (tên bảng, tên file test), test kèm `02 §9.5` (factory). Quyết định khác mục *Việc cần làm* thì ghi rõ khác ở đâu và vì sao.
7. **Slice → *plan*.** Chia AC thành slice dọc (lite: một slice), mỗi slice có `acs`, `seam`, `tests` dự kiến, `files` sẽ đổi, `dependsOn`. Một slice là một commit, nên slice gom đủ các file của một hành vi (model + migration + test + tài liệu chi phối của nó). Hành vi đổi thì `grep -rn "<trạng thái hoặc field bị ảnh hưởng>" docs` (ví dụ `failed_at`) và đưa mọi mục mô tả nó vào `files`, kể cả sơ đồ và kịch bản test, thay vì đợi phase 5. Code phá huỷ hoặc gọi I/O (DROP database, HTTP, `subprocess`) test ở seam bằng kết nối giả, như `shared/tests/test_reset_db.py` (PR #27); `untestable` chỉ cho AC cần hạ tầng thật không giả được, kèm cách kiểm tay. Ghi bằng `state.py push <T> 'slices=[…]'` trước khi `set currentSlice` (`set` kiểm slice đã tồn tại), rồi `state.py check <T>` và `python S/scripts/check_ac_trace.py <T> --planned` (chỉ kiểm mọi AC đều có chỗ, chưa kiểm test tồn tại). Rồi `python S/scripts/plan.py <T>` in slice thành `plan.md` của ticket; slice đổi sau G1 thì chạy lại.
8. **⛔G1** (khuôn ở SKILL.md → *Gate*). Tin tóm tắt: `plan.md` vừa sinh (AC → slice → seam → test → commit); tài liệu chi phối; quyết định mới; file sẽ đổi (đánh dấu file trong `backend/shared/`); mode đề xuất; AC `untestable`. Hỏi: duyệt slice và mode (một câu), các quyết định còn mở.
9. Duyệt xong: commit *spec* + *plan* (và dòng `Status:` đã triage ở bước đầu), rồi chuyển phase; script từ chối khi `spec.md` thiếu `## Quyết định`, thiếu `plan.md`, hoặc chưa commit:

   ```bash
   python S/scripts/commit.py <T> --task plan -m "docs: plan <chủ đề> ticket" -- <thư mục ticket> [<spec.md của ticket đã triage>…]
   python S/scripts/state.py transition <T> --to code --gate g1 --next "S1: viết test red đầu tiên" --reason "G1 approved"
   ```

   In điểm clear.

## Xong khi

Mọi AC nằm trong một slice hoặc trong `untestable`; mọi file sẽ đổi có tài liệu chi phối và mọi lựa chọn mở có dòng trong `## Quyết định`; `plan.md` khớp state và commit `Task: plan` đã có; `state.py check` và `check_ac_trace.py --planned` xanh; `gates.g1` có ngày và `phase` là `code`.
